# sbt - switchbard terminal UI

Binary `sbt` (this crate). Run in a configured repository: `sbt`, `sbt stats`, `sbt paths`. First launch explains task references and stages, then offers suggested settings or customization; `sbt init --yes --task-prefix IW --status Inbox --status Done` configures without opening the UI. Install off a feature branch: `bash scripts/install-switchbard.sh --branch sbt` (guarded; stays installed until the branch is merged or deleted on origin, then main replaces it within a minute; TASK-272).

## Standing commitments (owner-set, 2026-09-02)
1. Everything the user might tune lives in Lua (`~/.switchbard/tui.lua`, hot reload). New feature => new config surface only if a user would plausibly change it.
2. Fast and findable: no action more than two keystrokes away; `?` must list it.
3. `:bug` / `:idea` work from anywhere and carry screen + action trail automatically.
4. Tests are E2E only (`tests/*.rs` by feature over `tests/harness/`): real key events, real backlog on disk, assert on rendered screen. No unit tests, no mocks.
5. Self-documenting names over comments. One module per concept.
6. Minimalism: cut what telemetry shows unused. Prove usefulness before adding.
7. This file stays under 50 lines and is updated every slice.
8. Telemetry (`~/.switchbard/tui-events.jsonl`) records key, action, timing, error. `sbt stats` is how we learn what is used, slow, or unbound.
9. Default keys are lowercase only (owner-set, 2026-09-17): never bind a shifted letter in `default.lua`, and never propose one; find a lowercase key or a two-key sequence instead. Users may still bind uppercase in their own `tui.lua`.
## Module map
- `app/agent_kill.rs` - configurable K (`kill_agent`) prepares native selected-PID identity off-thread; Cancel-default picker requires Enter and complete visible warnings. Core revalidates start/kind/cwd/executable and protects self/ancestors before positive-PID SIGTERM; no group/escalation/task edit/manual claim release. Normal dead-agent claim pruning remains. State/evidence: `docs/tui-agent-kill.md`.
- `app/task_cancel.rs` - `t c c` archives only the selected task after a fully visible confirmation; Enter/Esc keep it. Core snapshot guards read authoritative storage for detail edits and reject changed records; children and live agents remain unchanged. Detail sections initially expose every modeled field; `z` toggles, `Z` collapses all, `A` expands all, and header clicks fold without writes.
- `app/pr_merge.rs` - m prepares merge off-thread; shared confirmation picker defaults to Cancel, digits explicitly confirm a method. Full repo/PR/head/base/viewer must fit before confirming. Pending submits block duplicates, quit and reexec; page switches retain concise result alerts. Verification prose and receipt paths stay in telemetry and the retained core result, not success chrome (`docs/tui-merge-result.md`). A confirmed merge (never a rejection or an unknown outcome, TASK-204) tells `pull_requests.rs` to expect it; that expectation is the one writer for post-merge fast-poll and the pending row/header state.
- `pr_notifications.rs` - bounded session PR change/availability alerts across pages; n dismisses latest. After first PR visit, refresh continues on Tasks. O opens selected PR in the browser.
- `page.rs` - Tasks / Pull Requests / Agents / Inbox identity and allowed actions; Tab (`page` in Lua) cycles through the four pages, and the header marks the active page. `agents.rs` renders repository-scoped live Claude/Codex sessions from the bounded core scan, including activity, title, status-line metadata and held tasks; it has no persisted list settings or writes. `pull_requests.rs` caches bounded repo reads off-thread; `pr_view.rs` renders the list/detail. PR refresh uses `pr_refresh_seconds` (default 60): the first observation row counts down, shows refreshing in flight, and restarts on completion (including failure); r retries immediately. While a confirmed merge hasn't converged (row gone or merged) it fast-polls every 3s for up to 90s, the header says "syncing", and the affected row's State cell shows "merging" (TASK-204); expiry without convergence notifies and returns to the routine cadence. The source includes Open/Closed/Merged, initially 100 rows; `:more` expands by 100 up to 1000 with explicit partial coverage. `/`, `f`, `s`, `p`, `c`, numbered headers and `v` reuse shared controls with independent PR state; `status:`/`lifecycle:`, `tasks:`, `checks:`, `review:`, `merge:`, `draft:` and `title:` read cached PR fields. Sorting retains selected identity; painting never writes PRs; Enter toggles the right detail pane, j/k select rows, Ctrl-d/u scroll details. Metadata survives optional active-check enrichment failures. State/Tasks/Checks use compact widths; Tasks shows an ID or link count, absent links a dash. Checks shows only check observations (closed/merged: NF, expanded to Not fetched in details); review and merge observations remain separately labeled in details.
- `app/` - `mod.rs` state, loop, browse keys, commands; `pickers.rs` column/filter/sort pickers + the shared picker key handler; `new_task.rs` the Tasks `t n` title draft and native create; `task_parent.rs` the `t a` existing-parent picker (ID/title search, native reparent); `task_status.rs` / `task_project.rs` the `t s` status and `t p` project native edits with stable task IDs; `paint_flow.rs` the `p` flow; `slots.rs` the shared `v` open/save/global/name/delete pickers and Tasks `v l` line wrapping, `v n`'s one-line name input (`Mode::RenameView`); `detail_edit.rs` the Tasks detail pane's focus, row cursor, field editing (`Mode::DetailFocus`/`DetailInput`), `PageDown`/`PageUp` pane scrolling and mouse routing (`handle_mouse`); `filter_completion.rs` the `/` editor's Tab completion, shared by Tasks and PRs: keys from the page's column catalog, values from the same list `column_values` gives the `p` menu, live ambiguous-candidate line under the editor, Esc leaves the filter unchanged.
- `view_history.rs` and `view/history_picker.rs` - automatic per-repo history capture and the `v h` picker; each visible entry is a compact card with its own title, time and miniature table; `view/history_title.rs` supplies plain-language titles and `view/history_preview.rs` reuses read-only projections over current cached data; Enter restores an arrangement and `v s <number>` deliberately promotes it to a slot. Capture is deduped globally with move-to-front and bounded by age, count, file size and entry size.
- `picker.rs` - the one list every menu uses: typed `PickOption` payloads, numbered/lettered rows, type-ahead; `app/` dispatches on payloads. Task/view menus and column/settings/paint-rule actions are selectable rows; the column filter menu appends `(shown/total shown)` to columns with active field filters, including hidden columns. Mutation menus require Enter after type-ahead. A bounded parent stack supports ←/h back and →/l open, with Esc closing all; filter-value initials h/l keep typeahead precedence when matching a label (arrows always navigate); merge confirmation retains explicit authorization. Short pickers scroll to selection; results stay in the footer. A digit in browse opens that column's `ColumnActions`.
- `detail_pane.rs` - shared task/PR split, border, bold title, muted metadata, accent sections, wrapping and bounded scroll; `FieldRow`/`field_rows` list the Tasks pane's one navigable row order for both `detail_edit.rs` and rendering, and its own description row's full body renders as extra lines beneath it (read-only; `sb edit --description` is the edit path), scrollable via `PageDown`/`PageUp` or a mouse wheel without moving the cursor. `Hit` (set every frame from `view::draw`) is the one source of "which pane, which row is at this coordinate" `App::handle_mouse` routes clicks/wheel against. A second Tasks `open`/`l` (or a pane-row click) focuses the pane for `j`/`k` row navigation and Enter edits a row; PR Enter still just toggles its own read-only split, Ctrl-d/u or a wheel scroll it.
- `page.rs` / `inbox.rs` - Four-page navigation with blank Inbox; shared `attention_badge` counts all open PRs.
- `tty.rs` - the terminal as an event source and a line that can hang up: `event::read` lives on its own thread and a `POLLHUP` watch flips the shutdown flag, so the main loop only ever waits on a channel and flags (crossterm spins forever on pty EOF; TASK-232). `scripts/test-sbt-tty-hangup.py` (`mise run test-sbt-hangup`) proves both exits against a real pty.
- `view.rs` - rendering only (the table is hand-drawn so headings span the row); snapshots the screen text for reports. TASK-235: the title line holds only the repo chip, shown count and view name; the filter gets its own wrapping line inside the frame (omitted when empty) and every other view setting moves to the footer hint bar, truncated before the key hints ever are. TASK-234: header cells split the numeric key (`keys` surface) from the column name (`header` surface).
- `column_values.rs` / `filter.rs` / `sort.rs` - explicit Tasks/PR adapters, one matcher and deterministic sorting; `shortcuts.rs` owns action names, aliases, page availability and help order.
- `list_presentation.rs` owns bounded terminal layout inputs; `list_settings.rs` owns feature scope and capabilities.
- `columns.rs` - the column catalog: one `ColumnSpec` row per column (name, header, width, field, vocabulary) plus `values`/`cell_text`; every other module asks it.
- `config.rs` - `default.lua` baked in, user file layered over; keys, theme, glyphs, palettes. Theme = named `Surface`s (title chip, header band, heading, selected, label, link, chip, keys, hint...) each a Style (fg/bg/modifiers), `theme.columns` maps columns to surfaces, and `theme.highlights` names the fills (`highlight.rs` derives an undeclared slot from the palette at a fixed OKLCH step off the canvas). Any role may take a bg; only a fill no ink in the theme reads on is refused (`legibility.rs`, the same APCA math the gates use).
- `tasks.rs` - task load + filter language (`status: pri: label: project:` + words, loose match: `status:todo` == "To Do"); `field_values` feeds the `f <n>` picker.
- `views.rs` - `ViewState` (filter, sort, columns, glyphs, paint, group, row layout, name) is what a slot saves and a restart resumes, one Lua record for both; global `~/.switchbard/views.lua`, per-repo overrides in `views/<repo path>.lua`; PRs use `.prs.lua` beside these files. The same Lua representation is also used by the per-repo `.resume` checkpoint and `.history.json` arrangement records. `vs<n>` saves to repo, `vg<n>` promotes to global; slot 1 opens. `v n` names a slot (writes the repo override if one exists, else global), `v x` deletes one; an unnamed slot's label is derived from its contents (`ViewState::label()`). Both page states survive Tab/restart.
- `date_fields.rs`: `p` offers When task filed / When merged in UTC buckets; authoritative creation/merge dates only. `paint_eval.rs` chooses semantic tokens; terminal conversion stays in `paint.rs`.
- `paint.rs` / `paint_eval.rs` - full emphasis styles, cell-scoped stop (`!`), and one fill per cell: `paint_eval::compose` splits a rule into its fill (a `theme.highlights` slot `h1`..`h9`, or any role carrying a bg) and the ink over it, so `h2`, `h2+alert`, `band+red` and `alert+p3` read the same way and two fills on different scopes coexist. `p e/g/h/t` targets selected values, groups, headers and navigation/title, and every scope then asks highlight (step 1: none/band/`h1`..`h9` swatches) before text (step 2: keep default ink, roles, colors, palette; Space adds a token, Enter applies, `←` back) - `app/paint_flow.rs`'s `PaintDraft` is the one authority while they are open and `paint_eval::compose_text` writes the rule (TASK-245). `:paint` replaces a validated rule list. Theme backgrounds, role composition and reading gates are documented in `docs/emphasis-roles/guide.md`. `p` rules in a hierarchy: `by:<col>=v:c,...`, `rows:<filter>=c`, `column:<col>=c`. Automatic palette choices persist as `p<n>` tokens and resolve against the current palette; explicit colors remain literal. Top rule is the base (whole rows); lower rules paint only their scope. `po` reorders.
- `group.rs` - `Grouping` (0-2 nested levels, `project›goal`): `o` picks it; headings over the filtered, sorted order carry project def status, done/total, or goal week actual/target, pace. Explicit outlines also nest within the Planned section while preserving its canonical order.
- `ball.rs` - who holds the ball: `ball:me`/`ball:agent` labels (`dispatching` = agent); `b` cycles. `tg` / `:goal <name>`: attach or detach the task to a goal.
- Live work (core `work_sessions`, TASK-150): `work` column = one ● per live session (`sb work claim`), the `working` band and the row's text pulse on a soft-clipped sine (`work.period_ms`, `work.frames`, `work.flatten`); the declared `working.bg` is the floor the band never dims below and the pulse brightens in OKLCH lightness only, never hue, from there: 20% on the dark presets, 12% on `light` (`oklch.rs`'s `WORK_LIGHTNESS_SWING_DARK`/`_LIGHT`, TASK-241); the footer's view-settings summary counts `working:N` (TASK-235), detail names sessions; `w` passes the task (ends every claim).
- Planning is independent of status: `t l` edits Considering/Planned, `o l` groups by Planning. In the filter picker, `f` then `pl` reaches Planning even when hidden; `p` selects Planned and `c` Considering. New views expose Planning, visual Progress (`%`, next to Status), and Checklist; Progress uses cached criterion coverage as a six-cell smooth blue capsule that turns red at 100% (`progress.rs`, partial blocks, - unmeasured), with `progress_style` pill/ascii/icons, theme progress_fill/complete/empty/shell surfaces, backwards-compatible `glyphs.progress` overrides and numeric sorting; saved views keep their columns. Checklist counts own + descendant criteria, excludes canceled branches, and shows Review at 100% until manually Done. `t r` orders Planned open tasks after migration (legacy repos retain expedite); `v p` shows/hides the section, `#` shows position. Planning writes use the core task+ranking boundary with stale-detail guards.
- `settings.rs` - `,` panel: hide statuses everywhere; per-repo file, `g` promotes to global.
- `report.rs` / `app/report.rs` - `:bug`/`:idea` capture context and save single-flight off-thread through core; a persistent Saving/result banner survives pages, pending saves defer quit/reexec, and `:` restores failed drafts. `app/task_refresh.rs` polls storage and coherent detail drafts off-thread, rejects snapshots superseded by local edits, and defers edit focus while loading; report completion selects the new task only if the original context is unchanged. `telemetry.rs` - JSONL log, trail, `stats`.
## Loop
Slice => commit on a `feat/tui-*` branch => gate below, then `bash scripts/install-switchbard.sh --branch sbt` => running sbt re-execs (`main.rs::InstalledBinary`, resumes view/filter/row) => user drives it => drain `label:tui`. The install is a one-way street (TASK-272): each slice must contain the installed commit (build on the same branch, or rebase onto it), and the auto-install agent replaces the build with main only once the branch is merged or deleted on origin.
## Gates
Per slice: `cargo fmt -p switchbard-tui -- --check && cargo clippy -p switchbard-tui --all-targets && cargo test -p switchbard-tui`, then the install above.
`mise run ci` uses the same flags (warnings denied by `[workspace.lints]` in `Cargo.toml`), so alternating with it reuses dependency builds; only crates whose features differ under `-p` rebuild. It runs every crate's tests, so run it once before merge.
