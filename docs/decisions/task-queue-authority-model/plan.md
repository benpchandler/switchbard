Status: execution contract only. Production implementation starts only after separate authorization of [backlog: TASK-80.3 To Do] and [backlog: TASK-80.4 To Do]. This package closes the contract decision carried by [backlog: TASK-80.2 Done].

## 0. Grounding and outcome spine

This plan executes the approved decision package. It does not reopen the authority split or authorize a real config, cache, task, or GitHub write.

- Source data: read-only GitHub GraphQL observations for explicitly configured `github.com` Projects and their delivery descendants, normalized by `[new: crates/switchbard-core/src/github_delivery/adapter.rs]`.
- Write path: source intent is persisted through config mutation methods added beside `Config` [exists: crates/switchbard-core/src/config.rs:21]; dispatch outcome is persisted through one native mutation added beside `edit_backlog_task` [exists: crates/switchbard-core/src/backlog/mutations.rs:50]. GitHub has no write path.
- Read path: immutable `DeliverySnapshot` values from `[new: crates/switchbard-core/src/github_delivery/types.rs]` feed the pure projection in `[new: crates/switchbard-core/src/github_delivery/projection.rs]`, then GUI state beside `dispatch_runs` [exists: crates/switchbard-gui/src/app.rs:143].
- Identity bridge: URL strings already stored on `BacklogTask.references` [exists: crates/switchbard-core/src/backlog/types.rs:222] resolve to opaque `(host, node_id)` keys; unresolved URLs remain local references and never join by guessed coordinates.
- Tenant key: every binding carries one repo root, matching the repo-scoped `BacklogRepo.root` [exists: crates/switchbard-core/src/backlog/types.rs:150]. V1 has no tenant or account write authority.
- Non-fatal failure: a failed refresh publishes `Stale` only when a successful snapshot exists and otherwise publishes `Unavailable`; field omissions stay `Unknown`; native task bytes and the prior successful cache entry remain unchanged.

## 1. What ships

After authorized implementation, Switchbard presents one deterministic Task Queue made of a local dispatch band followed by ordered, explicitly configured GitHub Project bands. Linked or adopted work remains a native row with nested delivery evidence; unlinked GitHub work remains a read-only projection. Every remote fact carries provenance and freshness, no GitHub result implies local Done, and successful dispatch release records its PR reference in the same atomic task revision as its terminal label, status, and note.

The implementation is two vertical milestones. TASK-80.3 first establishes a failing headless mixed-queue journey, then lands domain identities, source configuration, adapter, bounded cache, projection, shared native queue order, reference resolution, and atomic dispatch success behind no-GitHub-write tests. TASK-80.4 then binds those results into the existing Tasks / Dispatches route, begins from failing state-and-stress journeys, and closes with performance, live Lucella, rendered review, and human visual approval evidence.

## 3. Scope

### In scope

- Separate local, binding, Project membership, GitHub node, generic link, and queue-projection types with explicit observation state.
- An ordered default-empty `github_project_bindings` config field and validated add, move, and remove mutations for `github.com` Project URLs.
- A read-only adapter that requests opaque new-format global ids, observes Project membership and the issue/PR/check/commit/release/deployment chain, and preserves null, incomplete, inaccessible, rate-limited, and transport failures.
- One latest-success, versioned, viewer-bound cache file per binding, atomically written with a 500-item input limit and corruption isolation.
- One pure projection that preserves the existing local stack order, adds configured source bands, suppresses linked duplicates, retains all memberships, and excludes archived or closed remote history from next work.
- One core local queue selector consumed by GUI, `sb queue`, and the Rust fallback without an id re-sort.
- Generic URL resolution and explicit, race-safe local adoption without automatic task-URL rewriting. Adoption requires a resolved node, serializes by `(repo root, host, node id)` in the git common directory, rechecks links while reserved, and creates the URL reference in the same new-task write.
- One atomic and idempotent `RecordDispatchSuccess { task_id, pr_url, optional_note }` task mutation used by the Rust dispatcher, `sb queue release`, and the LangGraph protocol. It creates one canonical composite note entry and permits no post-success append.
- Existing IA V2 Tasks / Dispatches rendering, applicable design-state and stress coverage, 100-row disclosure, the established 40 ms frame-p95 ceiling, live Lucella read-only proof, and explicit human visual approval.

### Out of scope

- GitHub write-back, issue creation, Project field writes, PR actions, two-way synchronization, and any GitHub mutation.
- Remote-only per-item Switchbard rank, expedite, dependencies, claim, priority, or outcome fields; local adoption is the v1 boundary.
- Cross-repo interleaving through the hub ordering overlay, GitHub Enterprise Server, other forges, webhooks, historical snapshot ledgers, and typed link kinds.
- Automatic rewriting of user-authored task references after repository transfer or rename.
- Treating merged, released, deployed, known-empty, or refresh-success evidence as local outcome acceptance.

### Illegal states

- Duplicate binding locator in one repo scope, unsupported host, unknown binding id, or cross-scope move: reject before config serialization; config and cache bytes remain unchanged.
- Older refresh generation publishing over a newer one: reject at compare-and-publish; visible and cached snapshots remain unchanged.
- Wrong-version, wrong-viewer, wrong-binding, wrong-host, malformed, or over-500 cache entry: ignore that binding with a warning; other bindings and native tasks remain intact.
- 404, null node, or permission-masked response asserted as Gone: normalize to `MissingOrInaccessible`; never publish deletion.
- Omitted, failed, or truncated connection asserted known-empty: keep the field Unknown and publish no negative claim.
- Refresh attempting a task or GitHub mutation: impossible through the read-only port and rejected by test spies.
- Typed link written into string references, or unresolved coordinates guessed into an identity: reject input or leave the URL unresolved; create no side store or task.
- Adoption with no resolved visible node, a failed reservation, or more than one local task resolving to that node: reject before create and leave every task byte unchanged. Under the reservation, zero matches creates once; one match returns that existing id; concurrent callers therefore return the same id and never create two tasks.
- Remote projection ranked or expedited without adoption: reject target as not locally rankable; leave `backlog/ranking.yml`, tasks, and Project order unchanged.
- Dispatch success with a non-PR URL, a different replay URL, a different normalized optional note, or a write failure: task bytes remain identical and the claim stays `dispatching`. Replay of the same canonical URL and the same normalized optional note succeeds without a second note/reference. Blank optional caller text normalizes to none.
- Remote delivery evidence proposed as local Done: reject at the native mutation authority boundary.
