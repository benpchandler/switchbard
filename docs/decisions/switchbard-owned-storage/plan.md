# Central storage and repository exchange - Plan

## 1. What ships

Switchbard owns one machine-local database for every repository's native planning data. Linked worktrees share committed records immediately on the next CLI read and within two seconds in active GUI/TUI clients. Normal edits require no Git change or PR. An explicit export creates one optional lossless repository exchange file; collaborators import, edit, export and PR that file to exchange independent database changes.

This plan executes the detailed proposal for TASK-147 [backlog: TASK-147 In Progress], rechecked through the primary checkout CLI on 2026-09-08. It sequences implementation, not production cutover authorization. Start with lossless identity/migration fixtures and real multi-process transaction proof, then wire every consumer, then exchange and recovery, then coordinated acceptance.

## 3. Scope

In: stable repository/record identities; raw task, hierarchy, goal, rank and task-configuration data; transactions and replay receipts; explicit migration; change detection; all existing native consumers; deterministic single-file exchange with preview/conflict resolution; backup and restore; compatibility documentation and real state/stress evidence.

Out: hosted service, daemon, automatic Git operations, automatic import/export on task edits or checkout, field-level merge, machine preferences/executable views/process liveness/caches/logs/Git observations, and xplan-owned writes. Preserve these authorities and their references when task identity changes. No unrelated cleanup.

## 7. Risks and sequencing rationale

Lossless representation, implicit relationships and cross-process atomicity gate the implementation foundation. Migration depends on the central transaction and raw-payload representation; consumer cutover depends on registry-aware reads and versioned writes; exchange depends on stable identities, revisions and graph validation; production use depends on full consumer and recovery evidence. The detailed SQLite/format/whole-record merge defaults are proposals from the upstream decision for review, not claims that the owner already selected each one. No unresolved question blocks this plan's sequencing. Any fixture demonstrating an unrepresentable legacy record must stop authority cutover and resolve the affected mapping while preserving original data.

## Scope Drift

Creep: none. Shortfall: none in planned implementation scope. Product evidence and production activation are deliberately not claimed by this decision-stage plan.
